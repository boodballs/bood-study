# Project notes — Bood Study (study.boodautomates.com)

- Standalone Next.js 16.3.5 app (sibling of `site/`). Dev: `npm run dev` (port 3000 busy on this box → uses 3002). Prod build: `npm run build`.
- Stack: React 19, Tailwind 4, better-sqlite3 (`data/study.db`), Together.ai GLM-5.3-Flash (`TOGETHER_API_KEY` in `.env`, copied from `../site/.env`).
- Flow (primary): the CLIENT extracts text in the browser (pdfjs-dist for PDF — worker served from `public/pdf.worker.min.mjs`, mammoth browser build for .docx, FileReader for txt/md) — **the file never leaves the device**. Chapter detection also runs client-side (lib/chapters.ts is pure TS), so the picker appears with zero server round-trip. The client then POSTs JSON to `/api/generate/text`: either `{text, sourceName, sourceSize}` (single doc) or `{parts: [{title, text}]}` (picked chapters) → job → poll. Fallback: POST `/api/generate` (multipart) still works for rare client-extraction failures and .docx edge cases, including the staged-chapters flow via `/api/generate/select` (data/uploads staging + 24h sweep).
- Chapter AI calls run in PARALLEL (lib/job-runner.ts `runPartsJob`) — a 3-chapter deck takes ~one call's duration (~3 min), not 3×. Jobs report progress ("1/3") via the `jobs.progress` column; the client shows "Chapters done: n/3".
- GLM-5.3-Flash is a reasoning model: reasoning tokens count against `max_tokens` (set to 32000; 16000 truncated the JSON mid-array, `finish_reason: length`). JSON extraction is tolerant (fences/brace-slice) with one retry; failed raw responses are dumped to `data/ai-debug-*.txt`.
- Generation takes ~2-4.5 min. Freemium quota: **3 generations per WEEK** (Mon–Sun, Europe/Budapest ISO week) per account (logged in) or /IP (anonymous), tracked in SQLite `usage_weeks` (key `user:<id>` or `ip:<ip>`), counted on SUCCESS only. Plus a 5/10min burst limiter (in-memory). Quota errors return code `quota`. The landing page shows "Free: 3 study kits a week" + a live "This week: n/3" counter. Paywall-ready but NOT mentioned anywhere: `users.plan` ('free' default) + `weeklyLimitFor(plan)` — a paid plan would just raise the limit there.
- Abuse layer: (1) global daily fuse — `usage_days` key `global`, limit `DAILY_GLOBAL_LIMIT` (default 300, ~1 unit per AI call; multi-chapter decks burn one per chapter) → 429 `capacity` when hit; (2) Cloudflare Turnstile on anonymous generate + register — armed only when `TURNSTILE_SECRET_KEY` + `NEXT_PUBLIC_TURNSTILE_SITE_KEY` are set (create a widget in the CF dashboard first; without keys everything passes); (3) verification emails capped 6/day/IP (`mailip:<ip>` counter) so register can't be used as a spam relay; (4) deck pages are noindex,nofollow (kills SEO-spam incentive; decks are shared by link only).
- Accounts: email + password (scrypt `salt:hex`, 64 bytes — lib/auth.ts), sessions in SQLite + httpOnly cookie `study_session` (30d, sameSite lax, secure only when https). Registration REQUIRES email verification (login blocked with `verify-required` until verified). Password reset is self-service via emailed link. Routes: register/login/logout/verify/forgot/reset/resend under `/api/auth/*`, pages `/login`, `/forgot`, `/reset`, `/verified`, history at `/history`. Tokens (verify 24h, reset 1h) are single-use, stored sha256-hashed in `email_tokens`, 60s per-email cooldown, auth routes rate-limited 20/hour/IP.
- Transactional email via Resend API (RESEND_API_KEY + EMAIL_FROM in `.env`; `boodautomates.com` is verified in the Resend account, region eu-west-1). Branded HTML templates in lib/email.ts. All links use NEXT_PUBLIC_SITE_URL (canonical domain) — never derive from request headers (cloudflared rewrites Host to localhost:3003). Free tier: 100 emails/day, 3k/month.
- UI is ENGLISH-ONLY (user decision 2026-10-06): LangProvider hardcodes lang="en", no toggle; emails always sent in English; the HU dictionary + bilingual email templates remain in the code for a future re-enable.
- Test PDF generator: `node scripts/make-test-pdf.mjs /tmp/test-notes.pdf` (Hungarian photosynthesis lecture notes; uses DejaVu fonts for ő/ű).
- DEPLOYED: https://study.boodautomates.com — production via user systemd `boodautomates-study.service` (port 3003, `npm start`), routed by the boodautomates cloudflared tunnel (`~/.cloudflared/boodautomates-config.yml`, ingress study → 3003), DNS CNAME `study` → tunnel (created via the Cloudflare API token). Linked from the main site homepage "Free tools, built by me" section.
- Generation is ASYNC: POST /api/generate returns `{jobId}` instantly, the AI call runs in-process in the background, client polls GET /api/generate?job=<id>. Required because Cloudflare's ~100s proxy timeout (524) kills a 2-4.5 min synchronous response. Jobs tracked in the `jobs` table; jobs stuck queued/running >10 min are failed as `ai-failed` (server restarted mid-job).
- CAUTION: don't run `next dev` inside study/ while the production service is running — dev and build share `.next` and a dev session can clobber the production build (this exact race 502'd the MAIN site on 2026-09-30 when its own dev server raced a prod rebuild; the site dir has the same hazard).
- Stale duplicate cloudflared connectors cause intermittent 404s: check `cloudflared tunnel info <id>` — only ONE connector should be listed for the boodautomates tunnel (the systemd `boodautomates-tunnel.service` one).
- Email verification does NOT auto-login: verify link → `/verified` celebration page (no session created) → student logs in themselves. Reset flow unchanged (self-service link).
- Chapter picker (big books): docs >50k chars with ≥2 detected chapters show a picker BEFORE any server call (client-side detection). Up to 3 chapters → one AI call per chapter (parallel), merged into a single deck (chapter-headed summary/guide, concatenated cards/quiz/terms). Detection order: PDF outline/bookmarks → ALL-CAPS running headers (repeated caps page-headers = chapter starts; TOC pages listing ≥3 titles excluded; handles glued page numbers like "25RESTLESS BREATHING") → heading regex ("N. fejezet", "Chapter 3", "12. Capitalized Title", roman numerals). Verified on a real 269-page ebook (Breatheology): 12 sections detected via running headers. Docs >50k chars with NO detected chapters still fall back to silent head/tail truncation (user-approved).
